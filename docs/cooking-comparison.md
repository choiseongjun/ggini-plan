# 간편식과 직접 요리 비교

추천 조건 `mealMode`는 `ready`(간편식), `cook`(직접 요리), `mixed`(둘 다)다. 새 설정은 mixed, 필드가 없는 기존 설정은 ready로 해석한다. 기존 cooking 설정은 간편식/밀키트 필터로 유지한다.

초기 직접 요리 4종은 `lib/cooking-recipes.ts`에 정의한다. 실시간 가격 비교가 아니라 한국 카탈로그의 등록 가격으로 계산하며, 판매 단위와 수량이 달라지면 해당 레시피를 제공하지 않는다. 음식 종류와 상품명에 명시된 주재료가 맞는 반대 준비 방식만 비교한다. 소고기죽을 닭죽으로 연결하지 않는다. 비교 카드에는 실제 재료 상품·사진·판매처 링크·사용량·판매 묶음 가격·보유 반영 후 추가 구매 금액을 표시한다. 모든 상품에 요리 대안이 있는 것은 아니다.

- 한 끼 비용: 사용한 재료의 판매 묶음 비율을 곱한 합계. 레시피 가격은 1인분 예상 재료비다.
- 장보기 비용: 모든 끼니의 재료를 상품 ID로 합산하고 주문·보유 묶음을 한 번 빼서 올림한 실제 구매 묶음 가격. 배송비와 추가 양념은 별도다.
- 직접 요리를 포함하는 예산 안내는 탐색으로 찾은 구성이다. 수학적인 최저가로 표현하거나 이 값보다 낮다는 이유만으로 추천을 차단하지 않는다.
- 영양은 재료의 출처 있는 등록값을 사용 비율로 합산한다. 달걀은 1개 가식부 약 50g을 사용한 예상치이며 미확인 영양이 있으면 해당 합계를 null로 유지한다.
- 원재료 표시가 미확인인 재료가 있으면 제외 조건이 있는 추천에서 제외한다. 알레르기 없음으로 간주하지 않는다.

재료 재고는 추천 상품과 같은 `shopping_progress.scope=products`에서 판매 묶음 단위로 관리한다. 기존 별도 ingredients 재고와 자동 병합하지 않는다. ‘먹었어요’는 모든 재료 재고를 한 트랜잭션에서 차감하고 `food_intake_logs.stock_item`에 `{kind:'recipe',ingredients:[{item,packs}]}` 스냅샷을 저장한다. 취소는 현재 레시피가 아닌 당시 스냅샷으로 복원한다. 기존 단일 상품 로그는 그대로 지원하며 DB DDL 변경은 없다.

공유 스냅샷은 meals/products에 메뉴를 유지하고 purchases에 중복을 합친 상품·재료를 추가한다. 과거 공유 스냅샷에는 기존 products 구매 표시를 사용한다.

검증: `tests/cooking-recipes.test.ts`에서 묶음 합산·보유 반영·레시피 조건·예산·영양 누락·섭취/복원·공유를 검사한다. `tests/food-intake-api.test.ts`는 테스트 계정으로 실제 API의 원자성·재요청·계정 격리·취소를 확인한다.
# 레시피 비교 데이터와 가격 기준

- data/recipe-comparison.json: 기본 레시피 7종, 원재료 18종, 1인분 사용량/단위, 조리 순서, 원재료 제외 항목, 상품 연결 계약 및 상품 출처 URL. 조리법은 앱의 기본 예시(editorial)로 명시한다.
- data/cooking-recipes.json: 장바구니·섭취 기록에 사용하는 기존 실상품 요리 4종과 판매 묶음 계약. 기존 수량/재고/영양 동작을 유지한다.
- 가격은 별도 가정값을 저장하지 않고 /api/catalog가 제공하는 기존 DB의 price, price_checked_at, product_url을 사용한다. JSON에는 판매 묶음 용량과 매칭 조건만 둔다.
- 상품명/용량/단위/URL/국가/통화가 계약과 일치하고 유효한 가격 확인일과 양수 가격이 있을 때만 계산한다. 가격 확인일은 화면에서 볼 수 있으며 실시간 시세로 표현하지 않는다.
- 가격이 없으면 null이다. 가격 미확인 재료의 구매 묶음 수와 잔여량도 null이며, 임의 포장 단위나 범위로 채우지 않는다.
- 일부 가격만 있으면 확인된 사용분/구매 소계를 표시한다. 전체 비용과 저렴함을 주장하지 않는다. 사용분 전체 비용은 모든 재료 가격이 있어야 표시한다.
- 미확인 재료를 보유 체크하면 추가 구매는 0원이지만, 이미 가진 재료의 소비 원가는 여전히 미확인이다.
- 비교 화면은 1인분 사용량 기준으로 고정한다. 합계는 100원 단위로 반올림한 예상 비용, 재료 행은 사용량 원가를 보여준다. 판매 묶음 가격은 접힌 출처 상세에만 표시하며, 구매 수량/보유 체크 UI는 제거했다. 실제 재고·지출·섭취 기록은 수정하지 않는다.

신규 재료 연결 시 상품의 실제 형태(생쌀/즉석밥, 생고기/조리육), 전체 판매 용량, 표시 가격, 출처 URL과 확인일을 검수하고 데이터 계약을 추가한다. 검증 없이 상품 이름만으로 자동 매칭하지 않는다. tests/recipe-estimates.test.ts는 데이터 참조와 단위를, tests/recipe-product-comparison.test.ts는 미확인 가격·소계·보유·가격 갱신을 검증한다.

## 컬리 원재료 18종 연결

`recipe-ingredient-offers.json`에 공개 상품 페이지에서 읽은 이름·용량·가격·URL·확인일·상품고시를 보관한다. `recipe-ingredient-import.json`은 검수한 사용 단위와 판매 묶음 환산값이다. 쌀은 생쌀 4kg, 우유는 1L=1000ml, 달걀은 20개를 적용한다. 중량이 상품명에만 있는 버섯·설탕은 해당 필드를 용량 근거로 명시한다.

`node scripts/collect-recipe-ingredients.mjs --collect`로 공개 판매 데이터를 수집하고, `node --env-file=.env.local scripts/import-recipe-ingredients.mjs --prepare`로 신규/기존 상품을 구분한다. 원재료 형태와 용량 근거를 검수한 다음 `--apply`로 14종 신규 상품과 전체 18종 연결을 적용한다. 기존 4종 상품과 사용자 재고·기록은 수정하지 않는다. 현재 수집 시점의 가격이며 자동 실시간 갱신은 아니다. 판매 용량이 변경되면 재검수가 필요하다. 전체 성분 검수가 안 된 상품은 제외 조건이 있는 비교에서 계속 제외한다.
# 재료 상품 비교

직접 요리 카드의 `재료 상품·가격 비교`에서 검수된 대체 상품을 고를 수 있습니다. 기본 상품을 포함해 채소 믹스·현미 즉석밥·두부·생달걀 각 3종, 조리된 닭가슴살 2종을 연결했습니다. 여러 판매처의 실시간 최저가 비교가 아닌 등록 가격 기준입니다. 생쌀과 즉석밥, 생닭과 조리된 닭가슴살은 교차 대체하지 않습니다.

추가 7종의 가격·판매 용량·이미지·출처는 `data/cooking-alternative-evidence.json`에 보관합니다. `node scripts/extend-cooking-alternatives.mjs --collect`로 공개 페이지를 확인하고, `node --env-file=.env.local scripts/extend-cooking-alternatives.mjs --apply`로 없는 상품만 추가합니다. 기존 상품과 사용자 기록은 덮어쓰지 않습니다. 달걀은 개수로 환산하며 껍데기 포함 판매 중량을 영양 계산에 쓰지 않습니다(`grams: 0`은 가식부 중량 미확인).

여러 재료를 동시에 바꿀 수 있도록 검증된 조합을 생성합니다. ID는 데이터 그룹 순서대로 `--with--상품ID`를 붙여 저장하고, 한 재료를 바꿀 때 다른 재료 선택은 유지합니다. 그룹 순서를 변경하면 저장 ID가 달라지므로 기존 순서를 유지합니다.

`data/cooking-ingredient-alternatives.json`은 상품 ID·이름·판매 구성·용량·출처를 고정합니다. 용량 또는 출처가 변경되거나 가격 확인일·KR/KRW 정보가 없으면 대체 후보를 만들지 않습니다. `--with--`가 포함된 요리 ID로 선택을 유지하며, 사용량을 새 판매 용량으로 환산하여 구매·보유·섭취·공유에 같은 재료를 사용합니다. 영양 정보가 없는 상품은 미확인으로 처리합니다. 자동 추천은 기본 요리만 사용하므로 상품 변형이 메뉴 다양성으로 중복 계산되지 않습니다.
