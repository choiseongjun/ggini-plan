# 식사 재사용과 분석 운영

최근 8개의 저장 묶음을 홈에서 다시 불러온다. 음식별 양 수정과 제외가 가능하며, 로그인한 사용자의 원본만 서버에서 조회한다. 기존 영양값을 분량 비율로 환산하며 미확인은 그대로 유지한다. 과거 사진·구매 비용·재고 차감은 복제하지 않는다. 새 요청 ID로 묶음 저장하고 응답 실패 시 동일 ID로 확인한다. 과거에 각각 따로 저장한 음식은 자동으로 같은 식사라고 추측해 합치지 않는다.

주간 통계는 열량·탄수화물·단백질·지방 확인 건수와 미확인 건수, 다음에 할 수 있는 기록 행동 하나를 표시한다. 기록 누락을 결식이나 영양 부족으로 판단하지 않는다.

분석 기본값은 개인 하루 5회, 서비스 하루 40회, 분당 2회이며 월 1,200회 제한을 추가했다. 제공자 용량 확인 전 기본 처리량을 늘리지 않았다. 일·월 갱신은 한국 시간이다. 실패 요청도 공급자 비용 발생 가능성이 있어 예약 횟수에 포함한다.

환경변수 PHOTO_ANALYSIS_PERSONAL_DAILY_LIMIT, PHOTO_ANALYSIS_DAILY_LIMIT, PHOTO_ANALYSIS_PER_MINUTE_LIMIT, PHOTO_ANALYSIS_MONTHLY_LIMIT로 조정한다. PHOTO_ANALYSIS_RESERVED_COST_KRW에 요청당 보수적인 예상 비용, PHOTO_ANALYSIS_MONTHLY_BUDGET_KRW에 월 예산을 설정하면 월 횟수는 두 값으로 계산한 횟수와 월 제한 중 작은 값이다. 실제 청구액을 보장하는 결제 차단 장치는 아니다. 공급자 계정의 지출 한도도 별도로 관리해야 한다.

성공 응답은 photo_analysis_usage 운영 로그에 모델, 지연 시간, 입력·출력 토큰 수를 남긴다. 음식·사진·계정 식별자는 남기지 않는다. 이는 토큰 사용량이며 비용 자체가 아니다. 공급자 청구 내역과 실패 요청을 대조해 요청당 예상 비용을 정한다. 가격이 미확인된 상태에서 임의 요금을 실제 원가라고 표시하지 않는다.

이번 변경은 DB 컬럼 추가를 요구하지 않는다. 최근 식사 재사용은 기존 request_id 묶음을 사용한다. 월간 예약 건수는 기존 photo_analysis_requests에서 계산한다.
