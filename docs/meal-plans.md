# 맞춤 식단 백엔드

## 데이터베이스

`npm run db:migrate`로 로컬 PostgreSQL에 반영합니다. 기존 데이터는 유지됩니다.

- `body_profiles`: 사용자별 최신 신체 정보와 `diet_preferences` 설정.
- `meal_plans`: 생성 당시 신체 정보, 선호 설정, 서버 계산 결과, 메뉴 변형 번호, 알고리즘 버전, 생성 시각을 저장합니다. 사용자 외래 키와 최신순 조회 인덱스가 있습니다.

## API

- `GET /api/profile`: 로그인한 사용자의 최신 신체 정보와 선호 설정.
- `PUT /api/profile`: 신체 정보와 선호 설정 저장.
- `POST /api/meal-plans`: `{ profile, diet, variant: 0 }` 입력으로 서버에서 식단 계산. 비로그인은 저장하지 않고 `200`, 로그인은 프로필 갱신과 식단 이력 저장을 하나의 트랜잭션으로 처리하고 `201`을 반환합니다. 응답은 `{ plan, saved }`입니다.
- `GET /api/meal-plans`: 로그인한 사용자의 최근 식단 최대 20개를 최신순으로 반환합니다. `{ plans: [...] }`의 첫 번째 항목으로 화면을 복원합니다.

사용자 ID는 요청값이 아닌 세션에서 결정합니다. 입력이 잘못되면 400, 다른 출처의 변경 요청은 403, 자동 추천 불가 조건은 422, DB 오류는 503을 반환합니다. 조회는 로그인 필수(401)이며 모든 응답은 캐시하지 않습니다.

재료별 영양값과 레시피는 현재 서버 코드의 대표값으로 계산합니다. 상품 DB의 실측 영양값이나 구매 가격과 자동 연동한 추천은 아닙니다. 이력에는 생성 결과를 그대로 저장하므로 레시피 변경으로 과거 식단이 바뀌지 않습니다.

## 검증

`npm run test:meals`는 계산, 제외 식품, 식사 시간, 서버 입력 검증, 비로그인 미저장, 사용자별 데이터 분리, 생성·조회 및 프로필 저장을 검증합니다. 통합 테스트용 사용자는 종료 시 정리됩니다.
