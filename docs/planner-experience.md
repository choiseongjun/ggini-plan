# 추천과 장보기 흐름

- 기본 입력은 기간·끼니·예산이다. 목표·조리·제외 재료·예산 가이드는 더보기 안에 있고 현재 적용 조건은 밖에 표시한다. 마이 설정에서는 더보기를 연다.
- 추천 이유는 실제 표시 영양, 조리 조건, 등록한 보유 수량으로 계산한다. 열량 참고값과 20% 이내일 때만 가깝다고 표시한다. 영양 미확인 상품은 영양 적합성을 주장하지 않는다.
- 추가 구매 요약은 남은 식단의 판매 묶음 수와 주문·보유 수량을 반영한다. 판매처는 URL 호스트별이며 배송비·할인·최종 결제금액은 확인되지 않았다고 표시한다.
- 한국 플래너의 방문, 성공한 추천, 실제 변경된 메뉴, 등록된 판매 링크 클릭을 집계한다. 30일 동안 유지하는 무작위 브라우저 ID만 사용하며 서버에는 HMAC을 저장한다. 신체 정보·예산·상품명·계정 ID는 이벤트에 포함하지 않는다.
- 하루·브라우저·행동별 한 번 집계한다. 재방문은 지난 29일 중 이전 날짜 방문이 있을 때 표시한다. 스토리지 삭제·다른 기기·30일 식별자 교체로 추적이 끊길 수 있다. 행동별 지표이며 순차 전환율이나 구매 완료를 뜻하지 않는다.
- `/admin/metrics`에서 관리자만 최근 30일 날짜별 집계를 볼 수 있다. 로컬/프리뷰는 수집하지 않는다. 일별 네트워크 요청 제한 500회, 오래된 이벤트는 후속 요청에서 정리한다.
- 배포 전 `db/planner-events.sql` 적용. DB 테스트는 트랜잭션 롤백으로 기록을 남기지 않는다.
