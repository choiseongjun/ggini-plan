# 먹었어요: 실제 섭취 기록

홈의 구매한 음식 카드에서 `먹었어요`를 누르면 기본 1회분을 기록한다. `양 변경`에서 0.25·0.5·0.75·1·1.5·2·3·4회분을 선택할 수 있다. 식사 시각은 서버가 저장하고 날짜 조회와 표시는 한국 시간 기준이다. 기록 탭에서 날짜별 내역을 조회하며, 취소하면 식사 기록에서 제외하고 보유 수량을 복원한다.

## 영양정보와 수량

- 계정에 보유 등록된 간편식·밀키트 중 판매 구성과 1회분이 확인된 상품을 표시한다. 주문만 하고 받지 않은 상품은 먹을 수 있는 재고로 취급하지 않는다.
- 추천과 섭취 기록이 같은 `servingNutrition` 함수를 사용한다. 출처와 g 기준 표시 영양정보, 확인된 1회분 중량이 있을 때만 칼로리·단백질을 환산한다. 개수와 g/mL를 임의 환산하지 않는다.
- 미확인 영양정보는 null로 저장하고 합계에서 제외하며 누락 건수를 별도로 표시한다. 외식·직접 요리의 영양값을 임의 추정하지 않는다.
- 기록에는 당시 상품명, 영양값, 먹은 회분, 차감한 판매 묶음 수량을 보관한다. 카탈로그 변경 후에도 이전 섭취량은 바뀌지 않는다.
- 보유 수량은 소수 6자리 묶음 수량을 지원한다. 2회분짜리 한 묶음에서 1회분을 먹으면 0.5묶음이 남는다. 재구매 비용은 남은 회분을 먼저 반영하고 추가 판매 묶음만 올림한다.
- 실제 식사 기록과 기존 식단 계획은 구분된다. 이 기능은 계획의 완료 상태나 지출을 자동 변경하지 않는다.

## 저장과 충돌

`POST /api/food-intake`는 계정별 `shopping_progress` 행 잠금과 버전을 공유한다. 보유 수량 변경과 `food_intake_logs` 저장·취소는 한 트랜잭션으로 처리한다. 같은 UUID 요청의 재전송은 중복 차감·복원을 하지 않으며, 다른 화면의 오래된 버전은 409로 거절한다. 클라이언트가 전달한 칼로리·단백질은 사용하지 않는다.

로그인한 계정에 기록을 저장한다. 비회원에게는 기존 추천 기능을 유지하고 기록 시작 시 로그인을 안내한다. 판매처 주문 자동 수집, 사진 음식 판독, 직접 요리 재료 차감은 이번 범위에 포함하지 않는다.

## 적용과 검증

기존 환경은 `db/food-intake.sql`, 신규 환경은 `db/schema.sql`을 적용한다. 현재 DATABASE_URL에 새 테이블을 적용했다.

테스트: `node --env-file=.env.local --import tsx --test tests/food-intake.test.ts tests/food-intake-api.test.ts tests/shopping-progress.test.ts tests/shopping-progress-api.test.ts tests/shopping-plan.test.ts tests/shopping-plan-api.test.ts tests/shopping-personalization.test.ts`

부분 섭취, 미확인 영양정보, 잔량 계산, 중복 요청, 동시 수정, 계정 분리, 재고 부족 시 원자적 실패, 취소 복원, 한국 날짜 경계를 검증한다.
