# 끼니플랜 회원 정책 시행 전 검토

작성: 2026-09-20. 운영자 최성준 / choisj2702@gmail.com (운영자 확인 완료).

## 작성한 문서와 기능

- `/terms`: 회원가입, 연령, 무료 서비스, 외부 판매처, 추천의 범위, 계정·게시물, 이용 제한과 이의 신청, 이메일 탈퇴, 약관 변경.
- `/privacy`: 실제 코드에 근거한 가입 정보, 신체·식단·지출·커뮤니티·제보, 브라우저 저장소, 분석, 위탁업체, 삭제·권리 행사.
- 가입 시 약관·회원정보 수집이용·만 14세 이상을 각각 선택. 미리 체크하지 않음. 마케팅·신체정보 동의를 묶지 않음.
- 이메일과 Firebase 신규 가입 모두 서버 검증. 동의 버전과 서버 시각을 계정 생성과 함께 기록. 기존 회원의 동의를 소급 생성하지 않음.
- 기존 직접 Google OAuth 경로는 기존 계정 로그인만 허용하며, 새 계정은 동의 화면이 있는 Firebase 가입 경로로 안내.
- 기존 회원 로그인은 유지. 기존 회원에게 새 약관이 자동으로 적용되었다고 간주하지 않음.

## 확정이 필요한 실제 운영 정보

아래 사항은 코드/로컬 설정만으로 확인할 수 없어 문서를 **시행 전 검토본**으로 표시했다. 사용자의 명시적인 배포 요청에 따라 검토본 표시를 유지하여 공개한다. 공개 자체가 정책의 법적 검토 완료나 정식 시행을 의미하지 않는다.

1. **Vercel / Supabase**: 운영 프로젝트의 처리 국가, 저장 리전, 실제 계약 법인, 개인정보 문의처, 요청·오류·분석 로그 보유기간, 백업 보유·삭제 반영 기간. 상품 사진과 비공개 제보 저장소도 포함한다.
2. **Firebase Authentication**: 미국 처리 사실은 공식 자료에서 확인. 현재 프로젝트의 계정 보유·삭제 정책, 탈퇴 시 Firebase 사용자까지 삭제할 관리자 인증 수단·운영 절차를 확정해야 한다. 앱 DB 계정 삭제나 Firebase 클라이언트 로그아웃만으로 Firebase 사용자 레코드는 삭제되지 않는다.
3. **국외 이전**: 업체별 이전 항목·국가·시기·방법·목적·보유기간·연락처와 적용 법적 근거, 거부 방법·결과를 표로 확정한다. 제공업체 정책 링크만으로 이 고지를 대체하지 않는다.
4. **민감정보**: 현재 임신·수유 여부 및 건강 관련 추천 설정을 받는 별도 경로가 있다. 일반 가입 동의가 이를 포괄하지 않는다. 실제 민감정보 처리 범위를 검토하고 해당 기능에서 별도 선택 동의·철회 및 서버 검증·이력 보관을 연결해야 한다. 이번 회원가입 동의 작업에 구현된 것으로 오해하지 않는다.
5. **기존 회원과 시행일**: 이용약관을 언제부터 적용할지, 기존 회원에게 어떤 방식으로 공지·동의를 받을지 확정한다. 공지 없이 과거 동의를 생성하지 않는다.

## 이메일 탈퇴 처리 절차

가입 이메일로 요청을 받아 계정 소유를 확인한다. 비밀번호·인증코드·신분증을 요구하지 않는다. 요청에 대해 안내하고 법정 기한 내에 처리한다.

- 계정·세션·프로필·식단·공유·커뮤니티 등 연결 기록과 별도 의견 테이블의 외래키 동작을 확인한다.
- 제보 `photo_path`를 삭제 전에 확보하여 비공개 저장소 객체도 제거한다. 공개 카탈로그에 복사된 사진에 개인정보가 있는지도 확인한다. DB 행 삭제가 객체 삭제를 대신하지 않는다.
- Firebase 사용자를 별도로 삭제하고, 백업과 운영 로그의 삭제·보관 예외를 확인한다.
- 비회원 브라우저 저장정보는 원격 삭제할 수 없으므로 이용자에게 사이트 데이터 삭제 방법을 알린다.
- 불필요한 개인정보가 남지 않았는지 확인하고 결과를 회신한다. 이 문서는 삭제 도구가 아니며 이번 작업에서 실제 회원정보를 삭제하지 않았다.

## 배포 순서

운영 정보를 확정하여 문서 본문을 완성하고 검토본 안내·noindex를 수정한다. 정식 시행일에 맞춰 동의 버전을 확정한다. 검토본에 대한 가입 동의 이력이 정식 약관의 소급 동의를 의미하지 않으므로 정식 시행 시 필요한 동의를 별도로 받는다.

사용자의 배포 요청에 따라 `db/member-policy.sql`을 운영 DB의 `kkiniplan.users`에 먼저 적용하고 다섯 컬럼을 확인했다. 다른 서비스의 `public.users`는 수정하지 않았다. 기존 회원 동의는 소급 생성하지 않았다. 테이블 컬럼 추가 없이 앱을 먼저 배포하면 신규 가입이 실패한다.
