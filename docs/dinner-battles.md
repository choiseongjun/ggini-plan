# 한 끼 결승전

- `/battle`: 메뉴 2개로 공개 링크 생성. 오늘 화면에서 진입.
- `/battle/:id`: 가입 없는 투표, 득표율, 공유, 만든 사람의 마감·사진 인증·삭제.
- 만들기와 투표는 HttpOnly 기기 쿠키를 사용한다. 계정 로그인과 별개다. 쿠키 삭제·다른 브라우저에서는 관리 권한이 복구되지 않는다. 기기별 1표이며 본인 인증 투표가 아니므로 다중 기기/쿠키 초기화를 통한 중복까지 차단하지 않는다.
- 같은 기기의 선택 변경은 기존 표를 갱신한다. 투표·마감·인증은 같은 행 잠금으로 직렬화한다. 인증은 실제로 먹은 메뉴를 선택하며 득표 1위로 강제하지 않는다. 24시간 만료 후 투표 불가, 인증은 가능하다.
- 메뉴·사진·후기는 링크 소지자에게 공개된다. 검색 색인 제외. 실제 개인정보·식사 일기와 연결하지 않는다. 별도의 공개 목록은 없다.
- 사진은 디코딩 후 JPEG로 재인코딩해 EXIF를 제거한다. 입력 8MB/25MP, 저장 1MB 제한. 첫 버전은 PostgreSQL BYTEA에 저장하며 트래픽 증가 시 객체 저장소로 이전할 수 있다. 투표 삭제 시 사진·표도 삭제된다.
- 생성 제한은 기기당 최근 24시간 5개이며, 강력한 봇 방지는 아니다. 대규모 공개 캠페인 전 인프라 레이트 제한과 신고/관리자 숨김 기능을 검토한다.

## 적용 및 검증

`db/dinner-battles.sql`만 적용하면 된다. 전체 마이그레이션 스크립트에도 등록되어 있다. 기존 사용자 테이블 변경 없음. RLS 활성화, 공개 DB API 정책 없음. Next 서버 DB 연결만 접근한다.

`node --env-file=.env.local --import tsx --test tests/dinner-battle.test.ts`

통합 테스트는 무작위 별도 스키마를 만들어 API의 실제 SQL을 실행하고 finally에서 해당 스키마만 삭제한다. DB 연결이 없으면 통합 테스트는 건너뛴다. 중복 동시 투표·선택 변경·권한·만료·사진·삭제 연쇄·생성 제한을 검사한다.
